# M13.5 Live Readiness & Robustness Operator Package

This package is the handoff for a future real Quest + ND8 engineering session. M13.5 is software-only complete; this document does not authorize automatic hardware access.

## Software preflight (no hardware)

From the repository root, use the existing `.venv` and do not install dependencies:

```powershell
.venv\Scripts\python.exe -B -m integration.m13_5_readiness --summary-path <session-root>\m13.5-readiness.json --output-root <session-root>
.venv\Scripts\python.exe -B -m integration.m13_5_streaming --output-dir <session-root>\pc-only --summary-path <session-root>\pc-only-streaming.json --fault-summary-path <session-root>\pc-only-faults.json
```

The expected result is `READY` for readiness and `PASS` for both PC-only summaries. The warnings about untested ND8/Quest are expected at this stage.

Individual mode smoke commands are available without hardware:

```powershell
.venv\Scripts\python.exe -B -m integration.m13_5_runner --mode baseline --scenario stable --output-dir <session-root>\baseline --summary-path <session-root>\baseline.json
.venv\Scripts\python.exe -B -m integration.m13_5_runner --mode shadow --scenario stable --output-dir <session-root>\shadow --summary-path <session-root>\shadow.json
.venv\Scripts\python.exe -B -m integration.m13_5_runner --mode active --scenario stable --output-dir <session-root>\active --summary-path <session-root>\active.json
```

## ⚠️ USER ACTION — real baseline smoke

The user must physically prepare the approved ND8/Quest setup, confirm the correct COM port and visual scene, and decide the trial count. The existing known-good M8 baseline command remains the baseline path; it must be started only by the user after hardware preflight:

```powershell
.venv\Scripts\python.exe -B -m integration.m8_selection_cli --mode live-nd8 --com COM11 --data-root <session-root> --max-trials 1 --selection-plan free
```

This command is intentionally not run by Codex. It may require the verified external CPython 3.9 Neurodance runtime as documented by M8. Do not interpret a dry-run or readiness import as ND8 acceptance.

## ⚠️ USER ACTION — shadow then active

Run the real session in this order:

1. Baseline smoke: confirm Quest selection open/ACK, live score evidence, one final submission and clean trial close.
2. Shadow: feed the same live M12 evidence callbacks into `M135TrialRuntime(mode="shadow")`; M13 hypothetical stop is logged, but the baseline M6 final decision remains the only submission.
3. Active: only after shadow logs pass the engineering reporter, opt in to `M135TrialRuntime(mode="active")`; M13 may submit once through the existing M8 orchestrator.

The runtime API receives a time-ordered `DynamicStoppingSnapshot` through `observe(snapshot, trial_id, selection_id)`. It rejects stale IDs, duplicate/out-of-order windows and mapping mismatch closed; after submission it logs late evidence and never submits again. The real ND8 adapter and Quest process remain outside this software-only campaign and require the user-controlled live bridge.

## Analysis and acceptance

After a real session, point the tools at every `m13.5-session.jsonl` file from that session:

```powershell
.venv\Scripts\python.exe -B -m integration.m13_5_analyzer --input <session-root>\m13.5-session.jsonl --summary-path <session-root>\analysis.json --text-path <session-root>\analysis.txt
.venv\Scripts\python.exe -B -m integration.m13_5_acceptance --input <session-root>\m13.5-session.jsonl --summary-path <session-root>\acceptance.json --text-path <session-root>\acceptance.txt
```

Acceptance checks engineering semantics only: parseable logs, valid frozen mappings, contiguous windows, trial reset, mode semantics, exactly-once submission, expected ACK, no fabricated no-decision, no stale trial contamination and no `obj_N` leakage. It does not impose an early-stop-rate, accuracy, cognitive-load or significance threshold.

## ⚠️ USER ACTION boundary

The user performs EEG-cap/ND8 preparation, COM11 confirmation, Quest wearing, Quest GUI/controller actions and visual validity checks. Codex can run the software readiness, logging, analyzer and acceptance commands, but must not claim Quest/ND8 PASS from those commands alone.
