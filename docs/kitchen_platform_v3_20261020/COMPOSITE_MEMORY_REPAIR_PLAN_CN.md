## 内存检查结论与边界

已完成同一测试进程 10 次环境创建、注册质量观察器、开始紧凑记录、关闭、删除引用并主动 GC 的生命周期实验：

- 每轮 GC 后环境弱引用存活数均为 0；文件描述符始终为 5，没有复现环境对象或文件句柄持续泄漏。
- GC 后 RSS 从约 454MiB 上升至最高约 678MiB，最后约 624MiB；不能把 RSS 保留直接认定为不可回收泄漏。
- 独立五轮实验，GC 后 RSS 约 583MiB；仅在该测试进程调用 glibc malloc_trim 后降为约 376MiB，说明其中约 208MiB 是可归还的分配器保留内存。此调用仅用于诊断，不拟加入常规控制流程。
- 代码存在 `platform.post_step_observers -> quality.sample -> quality.platform` 强引用环；close 目前不解除观察器注册。回收依赖 GC，MuJoCo 原生模型/数据可能随之延迟释放。
- 同一进程池会重复执行多个任务；失败截图渲染器缺少覆盖异常路径的 finally；重放读取整条数值轨迹会产生瞬时峰值。

这些实验没有执行完整长任务，也没有覆盖驱动/GPU资源；因此目前不能声称已排除所有内存泄漏。诊断输出位于本机 `/tmp/kitchen_memory_probe_20261026.jsonl` 与 `/tmp/kitchen_memory_allocator_probe_20261026.json`。
