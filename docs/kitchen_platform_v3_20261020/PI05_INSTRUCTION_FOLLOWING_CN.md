# π0.5微调能否学到指令遵循、是否需要粗/细指令混合与指令dropout（调研）

2026-11-14。对象：`BCI_DATA/kitchen_v3_40pi_20261114`（3927条，98句粗指令×40条，见[采集大纲](COLLECTION_PLAN_V3_CN.md)），拟用openpi的π0.5微调。下文区分**文献/源码事实**与**本项目推断**；尚未训练，结论需实验验证。

## 1. 本数据集的事实（实测）

- **指令在决策点是必需的**：98句粗指令中91句从同一种随机初始场景出发（门开100°、餐盒在炉外、托盘空）；R3与R4共用“门关、餐盒在炉内”，R2与D03共用“门开、餐盒在炉内”。开局时取哪种水果/主食、是否清洗、是否加热、是否送餐，只能从指令得知。
- **中途决策点**：水果放好后（停止/接R5/接H/接B1）、主食放好后（停止/接B1）。这些时刻的画面在不同指令间相同，由粗指令的后半句决定。各选项样本数按指令均衡（每句40条）。
- **静止片段**：13–17%的帧处于≥0.4 s的静止段。唯一物理上必须的等待是清洗（约2.4 s，水流需≥2 s才判定清洗完成）；其余是专家的稳定等待，策略缩短它们无害。2 s加热在手臂到门前已完成，不再产生等待。
- **openpi源码（本机`~/Projects/openpi`）**：π0.5微调只有flow-matching动作损失，梯度同时进入动作专家和VLM主干；不训练子任务文本预测；prompt取自每帧LeRobot `task_index`；没有指令dropout；episode结尾的动作块用最后一帧补齐（学会停住）。默认30k步×batch 32≈96万样本，约为本数据6.7M帧的0.14轮。显存：推理>8 GB，LoRA>22.5 GB，全量>70 GB。

## 3. 判断（推断）

**能学到“菜单内”的指令遵循。** 本数据与LIBERO-Goal同类（同场景、语言决定目标），而π0.5在那里确实依赖语言。BCI端从固定菜单生成指令，正好落在模型擅长的“已训练组合”范围内；同义改写和新组合泛化不是本项目需求（若以后接自由语音，再做LLM改写/反事实增强）。

**主要风险不在开局选目标，而在长程中途和训练方式**：
1. 只用粗指令时，模型要从画面和后半句判断进行到哪一步、下一步做什么（停/R5/H/B1）。文献中扁平策略在这里最容易退回默认行为。
2. openpi全量微调会让动作梯度进入VLM，可能削弱语言作用（无knowledge insulation）。
3. 清洗等待：无记忆时可能提前关水（清洗不判定）或停在原地。
4. 默认步数只覆盖约0.14轮数据。

## 4. 建议

1. **粗/细指令混合：要做，作为默认。** 证据最一致（π0.5“训练含子任务数据”、MuGIL、Steerable Policies）。做法：
   - 两种导出视图：粗指令整条episode；细指令按阶段切成独立episode（结尾补齐为停住，正好对应“完成这一步后等待下一条指令”）。原子任务和C04粗=细，只放一份。
   - 长程任务中粗、细约各一半；再按任务类型加权，避免原子任务只占约6%的帧。
   - 部署两种用法都支持：BCI选整件任务时给粗指令；需要逐步控制时由外部按阶段下发细指令（openpi不能自己生成子任务）。
   - 长程任务要单独评估（MuGIL中混合训练反而让长程下降）。
2. **空指令dropout+CFG：第一轮不做。** 证据矛盾，openpi无CFG实现，推理计算翻倍；且π0.5的prompt里含离散化状态，只能丢任务文本。若评估发现模型忽略语言，再依次考虑：反事实标注、冻结/隔离主干、最后才是CFG。
3. **不要随机删减粗指令的分句。** 删掉“Finally, deliver…”就是另一个任务，会产生错误标签。合法的变体只有“剩余步骤指令”（只删已完成的分句），需要部署时有进度追踪，作为可选第三视图。
4. **同义改写：暂不需要**（固定菜单）。
5. **清洗等待**：先在评估里测“清洗未判定/卡住”的比例；若显著，优先给出可见的“清洗完成”信号或按事件计的进度输入，而不是按时钟计时。
6. **训练规模**：LoRA需>22.5 GB显存，本机16 GB不够，需24 GB以上显卡或云端；步数按0.14轮的现状至少加倍，并以决策准确率监控。

## 5. 评估协议（训练后必须做）

用≥100000的新种子：
1. **同一初态，换指令**：91句共享场景的指令逐一执行，统计每个决策点的正确率（选对水果/主食、洗/不洗、热/不热、送/停），不只看任务成功。
2. **指令消融**：空指令、错误指令。若成功率不崩（LIBERO-Goal应降到约10%），说明模型在走视觉捷径。
3. **粗指令 vs 外部逐段细指令**（仿真中用TaskMonitor做理想阶段追踪）：两者差距即“阶段判断”损失。
4. **清洗/等待**：清洗未判定、停滞超时的比例。
