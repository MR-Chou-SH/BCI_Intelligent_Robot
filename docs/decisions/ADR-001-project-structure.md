# ADR-001：采用模块化单仓库结构

- 状态：已接受
- 日期：2026-08-13

## 背景

项目需要长期协调 VR/SSVEP 刺激、脑电、视觉、场景理解、机械臂和系统集成。初始化阶段还没有足够信息确定各子系统的具体技术栈和部署方式。

## 决策

采用一个 Git 单仓库保存项目管理文档与各子系统的源代码入口，并按领域划分 `vr_stimulus/`、`eeg/`、`vision/`、`robot_arm/`、`integration/` 和 `experiments/`。架构资料、决策和进度集中放入 `docs/`；外部历史资料放入 `reference/` 并默认只读。

场景理解暂不单设实现目录。在确定其运行位置和接口前，其研究资料归档于 `docs/literature/scene_understanding/`，未来实现位置通过新的 ADR 决定。

## 理由

- 便于新手统一查看版本历史和项目状态。
- 在技术选型未确定时保持模块边界清晰。
- 让跨模块协议和实验记录与代码处于同一可追溯基线。
- 将历史参考资料与新开发代码明确隔离。

## 影响

- 各模块应通过明确接口协作，避免跨目录直接耦合内部实现。
- `reference/` 内容不得被当作可直接运行或维护的生产代码。
- 大型数据、生成物、Unity 缓存和可重建依赖不得进入 Git。
- 当部署或团队规模要求拆分仓库时，需要新增 ADR 重新评估。
