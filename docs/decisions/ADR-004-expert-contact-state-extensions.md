# ADR-004: 专家采集的接触状态与几何等价姿态

日期：2026-10-24。状态：本地开发分支实现中，逐任务物理验证进行中。

用户要求采集新表中20种原子实例和44种组合实例；旧V1.1任务目录和研究证据保持不变。复用现有FR3/UMI模型、DLS IK、位置控制器、碰撞与力学门禁，不添加运行时物体附着，不修改质量、摩擦、碰撞掩码或台面布局。

## 发现与决策

1. 球体姿态：苹果是位于body原点的单一35mm碰撞球，惯性三轴相等。相对转角不改变碰撞形状，但旧30°姿态差门禁在实际保持双侧夹持、平移滑移仅0.4mm时拒绝了抬升。仅对此严格几何／惯性条件按SO(3)等价类计算形状旋转差为0；椭球、网格、偏心球和承载物仍使用原30°限制。平移15mm、丢失50ms、实际角速度4rad/s、接触力40N等门禁保留。不得把该规则推广到非球形物体。
2. 双臂托盘：新增`arm=both`，仅允许target/payload为wood_tray，阶段acquire/carry/release。必须两臂各自两指垫均有实测夹持，共四垫，持续时间取共同保持窗口；两只手分别检查相对目标位姿，取最大滑移／转角。分离要求四垫全部分离，原单臂语义保留。不将一只手成功或平均位姿当成双臂成功。当前B1选择空托盘作为不变化的内容条件，未因此宣称递送已验证。
3. 自由托盘作为落放表面：旧过渡只支持固定世界表面，导致苹果在距离托盘底1.98mm处被拒绝，无法进入真实支撑接触。仅对具名tray_bottom增加“实际稳定托盘”判定：无夹爪接触、速度≤0.01m/s与0.05rad/s、倾斜≤5°、实际有静态有界面向上的承托且承托力至少为托盘自身重力65%。判定每子步重算；目标自身仍需已保持的夹持、既有支撑法向和位置关系。运动／悬空／手持托盘及其他任意自由物体不获该权限。保留1mm支撑柔顺、2mm普通净距和全部力／速度阈值。

## 数据与验证

新源码改变control hash，旧轨迹的任务PASS不会继承。新增回归测试检查球体与非球体差异、平移限制、双臂AND语义和仅托盘目标限制；稳定托盘过渡还须检查悬空／运动反例。每个专家实例只有在独立500Hz任务判据与完整控制重仿真通过后进入QUALIFIED_EXPERT索引；无论规划器是否结束，失败一律保留并排除。所有结果限定为MuJoCo仿真，禁止推广为真机安全认证。

4. 分散支撑力：原实现要求至少一个原生接触点的向上分力超过0.25N。固定场景中香蕉有6个接触点，各约0.196N、总计约1.177N，因接触离散方式被误判为无支撑；热狗抬升时也可能出现所有单点不足0.25N、合力充足的情况。改为对同一物体与其声明承托面的有效向上接触求合力，再比较既有0.25N门槛。每点仍必须法向向上分量>0.5、位于物体中心下方，接触检查还逐点执行1mm柔顺与40N上限。新增`support_force_policy=summed_upward_native_contacts_v2`和总力证据；弱合力、侧向／下压或错误承托面不能提供支撑。该变化会改变control hash，不继承旧策略PASS。回归覆盖真实香蕉的分散承托及总力不足反例。

## 2026-10-24 用户指示的临时变更（临时状态，交付前必须复核）

用户确认当前平台没有吸盘、软指、抱合夹具或凹槽等抗滚设施，MuJoCo 也不建模滚动阻力；圆球在平行双指垫之间可以无阻力持续转动。据此用户明确指示：若没有配套设施，就暂时禁用旋转阈值。

1. **番茄改用等半径球**：`layouts_v3.json` 的 013 布局新增 `tomato_primitive=equal_shape_sphere_v1`，`contact_v4.apply_contact_v4` 把 32×32×30 椭球改成 32mm 球，并把 body 上移 2mm 以保持静止底面在 0.800m 台面。这与第 1 条的球体规则一致，**没有修改门禁**；番茄因此成为与苹果同类的声明球体，而不是被放宽的椭球。
2. **`GRASP_RELATIVE_MOTION` 整条临时禁用**：用户看过香蕉在搬运中“绕长轴滚约 80°、同时沿指垫滑出 15.0067mm”的证据后指出：要真正解决需要改装指垫 mesh/软指，本轮先不做，因此指示把平移与旋转两个分量一起临时禁用。`contact_execution.GRASP_RELATIVE_GATE_ENABLED=False`，保留 15mm/30° 数值、`_grasp_within_limits` 双向检查和恢复开关；50ms 双侧夹持、抓持丢失 50ms、接触力（5N/40N）、载荷速度（0.3m/s、4rad/s）、支撑和普通净距门禁全部不变。`control_identity.configuration` 记录 `grasp_relative_gate="disabled_temporary_20261024"`。
3. **支撑柔顺临时提高到 1.5mm**：用户看过香蕉失败证据（托盘与香蕉端部胶囊静止平衡穿透 1.0211mm，超 1mm 上限仅 21µm）后，指示把 1mm 支撑柔顺临时调到约 1.5mm。`contact_execution.SUPPORT_COMPLIANCE_M=.0015` 为单行常量；普通净距 2mm、3mm 指垫柔顺、40N/5N 力、速度、抓持丢失门禁均不变。`control_identity.configuration` 记录 `support_compliance_m=0.0015` 与 `support_compliance_gate="raised_temporary_20261024"`。
4. **热狗承载物加装抬高扶手**：用户指示仿照汉堡的抬高横杆给热狗托盘加扶手、用扶手抓取。013 布局新增 `hotdog_carrier=raised_hotdog_carry_bar_v1`，`contact_v4` 把 `hotdog_grasp_left/right` 抬到局部 z=0.060、外移到 x=±0.082，并用两根立柱连接盘面；专家改用与汉堡相同的斜向横杆抓取，不再用低位侧柄。旧低位侧柄抓取实测指垫离热狗食物 1.9902mm（2mm 上限），抬高扶手让指垫从食物上方和外侧闭合。
5. **释放动作按指尖长度规划**：用户指出“直接多向上抬一抬”，并确认释放后要回初始位。`place()` 的释放抬升从 18mm 改为沿世界 +Z 抬 60mm（让 156mm 长指的指尖真正离开物体顶面）；`contact_execution.RELEASE_TRAVEL_M=.120` 单独放宽释放段的局部行程（接近段仍是 30mm），因为抬升必须超过原来的 30mm 上限。`end_contact` 通过后仍退开 20cm，`fruit()`／`meal()` 末尾调用 `return_home` 回初始位。恢复条件：指垫缩短或改用其他释放方式后，可把抬升和 `RELEASE_TRAVEL_M` 一起调回。
6. **2mm 普通净距临时去掉**：用户明确指示“把2mm限制直接去掉”，认为当前阶段这些余量无效。`contact_execution.ORDINARY_MARGIN_M=0`，`collision.certificate` 与 `payload_geometry.certificate` 的默认 margin 也改为 0；即**允许贴合**，但仍拒绝真正的穿透（distance<0）、5N/40N 接触力、3mm 指垫柔顺、1.5mm 支撑柔顺、抓持丢失和速度门禁。`control_identity.configuration` 记录 `ordinary_clearance_m=0.0` 与 `ordinary_clearance_gate="disabled_temporary_20261024"`。
7. **恢复条件**：更换指垫 mesh／软指／抱合夹具，或标定抗滚与滚动阻力后，把 `GRASP_RELATIVE_GATE_ENABLED` 改回 `True`；支撑柔顺改回 `0.001`（单行）后重跑全部受影响轨迹。在此之前产生的轨迹必须标注“相对位姿门禁已禁用、支撑柔顺已放宽”，不得当作完整专家质量证据，也不得据此宣称夹持姿态稳定。

该变更由用户直接授权，覆盖 ADR-004 第 1 条在“本阶段是否强制相对位姿门禁”上的执行，不改变第 1 条关于“球体形状等价”的定义。

## 2026-10-25：L2 短时速度与自有盘微小弹跳

用户明确允许无伤大雅的 pear／banana 携带速度放宽。实际报告区分了释放自转、短时再接触和真正滑落，因此不统一提高所有物体／设备的限值：

- 梨仅在 carry 且指垫尚未分离、或 release 且指垫已分离时允许 0.40m/s；香蕉仅在 carry 且双侧夹持或已实际承托时允许 6rad/s。其他载荷／设备保持 0.30m/s、4rad/s，原有释放自转豁免不变。抓持丢失 100ms、力与碰撞检查仍执行。
- 梨在 0.35／0.40m/s 两次复测后暴露出真实滑落，不继续提高上限。清洗后再抓取改成至少 8N／侧（初次放篮仍 4N），L2 pear 才通过最终承托、清洗标志和动作重仿真。
- 自有盘上食物的原生支撑可能在微米级弹跳时短暂消失。只对投影中心仍在盘内、间隙不超过 2mm 的情况容忍最多 100ms；超出范围／持续时间则失败。不会把缺失接触改成 supported，最终仍须自有盘的真实原生接触。新增测试覆盖超时、重复采样、越界和 clone 隔离。

这些参数与判据源码绑定在每份采集记录的 control identity；仍保留本 ADR 前述相对位姿门禁暂时关闭等局限。具体批次和右侧路径修复见 [2026-10-25 日志](../development_log/2026-10-25-kitchen-right-side.md)。
