# Kitchen 轨迹本身提速实验（2026-10-27）

用户要求缩短机器人实际执行轨迹的时间。默认 `standard` 保留原时序，新增可选 `faster`；本轮完成代表任务对照，不启动200条全量采集。

## 实现与限制

- 规划空载段请求速度乘1.4、携带段乘1.25，实际仍经原控制器限速。抓取/释放/设备接触阶段不提高请求速度，清洗、加热和稳定支撑等待保持原值。
- 右臂较长空载/携带直线路径复用现有连续IK路点流，只在整段结束收敛，减少每个路点的停顿；求解失败保留原路径回退。
- 左臂平滑路径在可执行时长范围内细化重定时。原先每次触发限速便增加40%时长，首轮苹果提速档反而35.20→36.64秒；新档改为较小增长步长，并在最后不可行/可行时长间二分细化，逐点复核原控制器约束。标准档保留原算法。
- 精细重定时曾导致 L2 banana seed1 在放盘前报 `NO_SUPPORT_BEFORE_RELEASE`。未放宽成功门槛；香蕉完整左臂技能恢复标准时序，并在退出或异常时恢复原档位，后续右臂技能仍可提速。
- B1双臂搬运本身的步长、抓持力和控制器参数未提速。组合任务收益来自此前的水果和主食操作。模型、碰撞/接触门槛、质量标准和记录格式均沿用原配置。

## 原生MuJoCo对照

以下均为实际仿真执行时长，不是播放倍率或程序墙钟耗时；不含录制前的初态准备。四对用例具有相同seed和逐元素相同的完整初始物理状态及初始偏置力。

| 用例 | seed | 标准档/秒 | 最终提速档/秒 | 缩短 |
| --- | ---: | ---: | ---: | ---: |
| L1 苹果直接装盘 | 0 | 35.20 | 30.64 | 12.95% |
| L2 香蕉清洗装盘 | 1 | 100.68 | 100.68 | 0%，保留标准时序 |
| R5 汉堡直接装盘 | 0 | 81.48 | 54.96 | 32.55% |
| D06 苹果+热狗装盘并送餐 | 0 | 209.80 | 157.00 | 25.17% |

最终四例均为 `QUALIFIED_EXPERT`，独立动作重仿真重算任务成功，最大qpos/qvel误差均为0。65项单元/回归测试通过，包括时长缩短同时保持限速/终点、右臂连续流的适用阶段、香蕉档位异常恢复；批量计划及同参数续跑计划均验证为100实例/200条，脚本语法和diff检查通过。

证据目录位于 `experiments/kitchen_platform_v3/collections/`：

- `motion_speed_pilot_20261027/`：标准对照及第一轮提速，各用例冻结的计划身份。
- `motion_speed_refined_20261027/`：精细重定时的中间结果，含香蕉失败报告，不作为最终合格结果。
- `motion_speed_final_20261027/`：最终四例、计划及 `comparison.json`，后者保存初态一致性、时长和配对报告哈希。
- `motion_speed_faster_plan_20261027/`：仅计划，未启动全量采集。

这是逐轮改进实验，标准对照与最终提速保留各自源码指纹；没有混写为同一冻结源码批次。最终档位尚未覆盖所有水果、种子、炉内取放和加热组合，不能据此承诺全部100实例成功或整批统一加速百分比。原有质量检验与有限重试继续生效。

## 使用

从仓库根目录执行；选用新目录，避免与原批次身份冲突：

```bash
bash scripts/collect_kitchen_dataset.sh \
  --output experiments/kitchen_platform_v3/collections/all_tasks_delivery_fast_20261027 \
  --motion-profile faster --samples-per-case 2 --jobs 2
```

先看计划可加 `--plan-only`，之后原命令加 `--resume` 开始。直接采集后中断续跑也加 `--resume`。档位同时写入 `plan.json` 和 `report.json`，不能在续跑中切换。无需额外渲染；初态、动作、关键状态继续按V3格式记录。
