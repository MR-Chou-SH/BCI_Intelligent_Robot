# SmolVLA 推理延迟与执行连贯性补测

此前8s realtime和60s lockstep只统计队列下溢/过期块，没有保留每次请求延迟或运动连续性指标，不能直接判为“平滑”。本轮增加可选`rollout --audit`，仅输出汇总，不记录图像之外的密集状态/动作日志，不改权重、控制器或物理参数。

测试使用已有1000步单示范SmolVLA checkpoint、同一L1 apple完整初态、RTX4060、512×512斜视RGB、25Hz控制、500Hz物理、每块50步、剩20步时提前推理、RTC开启、固定推理seed0。模型SHA256仍为`035500d965e5cd9c2fc6b3f33982bfe28842a59063c3b046b019488aefd6130b`。服务启动和试验结束后均正常释放资源，未操作硬件。

## 30s 实时结果

| 指标 | 平均 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 服务端处理一个50步动作块 | 178.1ms | 192.1ms | 198.9ms |
| 客户端完整请求往返 | 187.4ms | 201.2ms | 209.5ms |
| 观察构建，包括RGB渲染/编码 | 6.9ms | 8.6ms | 9.2ms |
| 观察开始→该块第一个未过期目标开始应用 | 210.2ms | 243.3ms | 243.5ms |
| 每控制帧限幅+20物理子步+判定 | 11.8ms | 17.0ms | 23.5ms |
| 相邻控制目标实际应用间隔 | 40.00ms | 41.69ms | 55.11ms |

首个请求487.8ms，观察→首动作498.4ms，作为启动warmup单列，没有混入稳态统计。服务端处理包含RGB解码、preprocessor、模型推理和postprocessor/CPU输出同步；不是纯CUDA kernel时间。完整请求往返再包含JSON、本机HTTP和响应校验。观察→目标应用不是夹爪或TCP到达目标的物理响应时间。

共750帧、25次推理（1次warmup，24次稳态），30s模拟、30.50s墙钟；下溢0、过期块0、guard触发0，反馈年龄通常5–6帧。每块覆盖2s动作，提前0.8s请求；本次约0.2s的推理往返在缓冲预算内。短时单场景测量，不是所有负载/任务的硬实时证明。

## 动作连贯性

**时间上的动作供给连续，但动作轨迹仍然不够平滑。**

- 750帧中748帧触发控制器限幅；原有最大关节命令速度仍为0.7rad/s，没有放宽。
- 接受后的关节目标速度差分加速度：P95 20.71rad/s²、最大35.0rad/s²。非边界帧P95 20.89，动作块替换边界P95 15.64，说明问题也存在于块内部，不仅是切块衔接。
- 左臂实测关节速度差分加速度：P95 5.25rad/s²、最大8.42rad/s²。按25Hz采样计算，未声称捕获所有500Hz瞬时峰值。
- 新旧块在同一未执行时刻的最大关节目标分歧：均值0.0139rad、P95 0.0366rad、最大0.0561rad；这是两个未来计划的分歧，不是已经执行关节的瞬时位置跳变。
- 所有关节命令中，前后速度幅值均>0.02rad/s的方向反转合计1462次（按关节累计）；没有活动左臂速度<0.01rad/s且持续≥0.2s的静止段。这是运动抖动证据，不是长停顿证据。
- 模型仍未完成苹果装盘。本轮测量不能把未训练充分、当前数据覆盖或RTC设置中的某一项单独确定为失败原因。

补充控制实验：原始专家动作通过同一有界执行器，26.72s成功、限幅0帧。关节命令差分加速度P95 0.218rad/s²、实测左臂差分加速度P95 0.232rad/s²；对应模型为20.71和5.25。该控制实验未渲染/未按墙钟限速，所以只比较以模拟时间计算的运动指标，不比较墙钟吞吐。两者轨迹和状态不同，也不把它当作RTC开关的因果消融。

结论：目前推理耗时并未造成队列断粮；持续动作供给已验证。平滑性仍不合格，块内目标噪声和频繁限幅需要后续处理。RTC的前缀引导不能代替模型本身的轨迹学习，也不是全轨迹限加速度控制。

## 使用与产物

```bash
bash scripts/kitchen_smolvla.sh serve --checkpoint <checkpoint目录> --device cuda --rtc --seed 0
bash scripts/kitchen_smolvla.sh rollout --trajectory <合格L1或R5轨迹> \
  --output <新目录> --clock realtime --seconds 30 --audit --video
```

`report.json/performance`保存统计；仅在`--audit`时采集执行/运动统计。客户端请求耗时保留最多4096条内存条目，输出稳态分位数与首请求摘要。统计不参与动作生成或修改控制目标。

本次产物：`experiments/kitchen_platform_v3/vla/smolvla_latency_20261109/`，包括`rtc_realtime_30s/report.json`、30s/750帧/25fps的正常速度`rollout.mp4`、`expert_motion_control.json`及`comparison.json`。

新增测试验证40ms采样单位、恒速段与块边界速度反转的差分指标、warmup与稳态分离。厨房127项回归全部通过，审计计数与时钟一致性、Git空白检查通过；所有现有数据与前一轮试验保留原位。
