# 2026-10-26 全任务运动连续性检查

用户要求优化左侧生硬轨迹，并检查全部任务的无理由回 home。保持已有分支与模型，未处理内存问题，未改变控制器速度上限、成功判据或布局随机化。

## 原因与实现

原 `line` 每 15mm 调一次 `point -> joints`，每个小点都等待实际关节收敛；水果原地变姿态又拆成 12 次等待。水龙头参考轨迹的自由段有数百个采样点，同样逐点收敛。这些停顿属于执行层，不能仅靠提高速度限值解决。

增加 `continuous_poses` 与 `stream_joints`：使用现有 IK 顺序预解、从当前关节姿态热启动，再按原控制器限速连续发送，整个路段使用一次起止速度渐变，仅末端等待收敛。左侧超过35mm的自由/携带直线及原地变姿态使用连续执行；抓取接近、释放、支撑接触等精细阶段仍使用原精确动作。水龙头自由接近/撤离保留参考关节路径并合并执行；实际抓持、转阀、开水清洗时长及关水检测继续逐帧保持。

固定1.28m的水果中转点在苹果 research seed0 超出工作空间。改为在1.28/1.24/1.20/1.16m有限候选中选可达的自由中转高度，同时要求高于抓取预备位置40mm，抓取姿态不变。苹果 seed0 的 L1/L2 已在本轮回归通过。

检查右侧还发现开门圆弧每0.5°都会等待收敛，改为沿原把手/铰链几何连续发送，保留末端等待与实际门角检查；预解失败时才使用原逐点路线。

香蕉 seed1 的旧失败通过完整初态＋实际控制重建确认：香蕉重1.1772N，托盘已有0.3474N向上支撑，夹爪仍夹持且承担其余重量。原逻辑要求松夹前托盘支撑达到总重量65%，造成反复微调和 LOAD_BALANCE_3MM_BOUND。香蕉现在沿用小盘的分担载荷释放流程：确认真实向上支撑、短暂稳定后逐渐开夹；保留松夹后静止支撑、指垫分离与2秒任务质量检查。未改变支撑判据、速度限制或最终成功标准。L1/L2 香蕉 seed0/1 已复测通过。

## 全任务回 home 检查

| 任务入口 | 当前连续接续策略 |
| --- | --- |
| L1 / C01 | 从当前位置接近水果、连续携带，结束在释放撤离姿态 |
| L2 / C02 | 放篮→水龙头→取水果→放盘直接接续，水龙头自由段不逐点停顿 |
| R5 / C03 | 从当前位置按主食几何规划并放盘 |
| R1 | 放炉后从实际撤离位置规划关门，不先固定回 home |
| R2 | 从当前姿态规划炉内抓取，取出装盘后直接规划关门 |
| R3 | 关门状态直接规划开门，不固定开门前/后回 home |
| R4 | 从关门后的当前位置规划按钮，再接开门，去掉固定回 home |
| C04 / C07 / C08 加热链 | R1→R4→R2 按上述实际状态接续 |
| C05–C08 左右臂衔接 | 左夹爪局部向托盘左侧撤离，检查整个手部包络退出托盘边缘60mm，再开始右臂；不固定回 home |
| B1 | 送盘、释放并撤离后结束，去掉终点后的双臂回 home |

所有任务入口中，`return_home` 仅剩三种有原因的兜底：当前姿态主食抓取规划失败、设备接近路径失败、局部左臂让位候选均不通过。实际运动前记录 `route_home_fallback` 及原因；规划尝试必须先于兜底，执行中的物理失败不会通过回 home 掩盖。保留有限简单路线，不引入全局规划器。
