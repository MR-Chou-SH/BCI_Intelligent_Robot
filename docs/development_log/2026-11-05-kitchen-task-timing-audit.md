## 汇总与采集预算

- 旧批次100条合格样本：录制段累计仿真 24874.20s（6.91小时），合格尝试累计墙钟 10074.92s（2.80 worker小时）。
- 另有4次失败尝试，累计 200.80s；包含它们约 2.85 worker小时。
- 以上是各进程耗时之和，不是批次从启动到完成的墙钟。
- 若粗略按旧批次耗时线性外推到200条，约5.6 worker小时（不含额外重试），两个进程理想约2.8小时；CPU竞争、调度和失败会延长。第二条seed也可能更慢或失败，不能视为当前版本200条的实测承诺。
- 后续主食/长组合已明显变快，但尚缺当前运动逻辑下各类任务的统一统计；不把旧表混合替换后计算所谓“当前总时长”。

## 为什么仿真时长与采集时长不同

采集路径是手动步进，没有sleep或按真实时间限速。物理仍500Hz，策略动作/关键状态25Hz。采集后完整独立重仿真一次，因此一次成功数据的实际成本包含两次物理演算及记录/检查/准备/规划开销。R2/R4等任务还需录制前物理准备，所以录制段很短也不一定采得最快。视频中的停顿来自被执行/记录的动作及等待，不把 Python 规划墙钟空隙自动变成相同长度的仿真等待。

进一步提速优先剖析执行/重放内Python与接触/状态查询开销，继续减少重复收敛和不必要等待，并以每条合格数据的含重试耗时评估；当前统计不通过降低成功门槛或跳过重放来缩短时间。
