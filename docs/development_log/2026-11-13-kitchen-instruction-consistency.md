# 厨房同一细指令一致化

2026-11-13，分支`feature/data-collection-improve`。目标：同一句细粒度提示词在原子任务和各组合任务里对应同一种动作，便于训练听指令的VLA。规则见[任务大表](../kitchen_platform_v3_20261020/TASK_CATALOG_V3_CN.md)“同一细指令一致化”一节。

## 判据

提示词相同、画面和本体状态也分不出来，却要求不同动作，策略只能学平均或随机选择，必须消除。差别能从观察看出（托盘上已有什么、左臂在哪里）时，同一提示词可以对应随状态变化的动作。

| 问题 | 处理 | 改动 |
| --- | --- | --- |
| L1/L2、D01/D02把水果放餐盘中心，有主食的组合放左半边 | 水果一律放左半边（局部X −0.11m，左臂一侧） | `execution.py` `FRUIT_TRAY_SLOT` |
| 香蕉只在有主食时转90° | 香蕉放盘一律先转 | `expert.place()` 不再看槽位 |
| 组合中左臂让位计入水果阶段，原子L1/L2同一时刻静止 | 让位改为下一阶段（R5/H）的开头，动作不变 | `run_case()` 先标记下一语言阶段 |
| 原子B1只有空盘 | 15种负载（空、4水果、2主食、8组合），提示词统一 | `catalog.py`、`prepare()`、`success.py` |

B1不按内容细化提示词：内容在画面中可见，送餐是同一技能；把内容写进提示词会把数据拆成15句各只有几条，推理时上层还要先知道盘里有什么。负载按初态逐种覆盖（与R3炉内状态同理），保证每种都有数据并能分组评测。带负载B1录制前按组合同样的放置摆好负载、双臂回初始位（不录制），初态检查负载完全一致，成功要求送达后负载仍在盘内。空盘B1实例定义不变，旧数据仍可校验。RL观测对B1仍以餐盘为目标。

## 验证

代码级：199项测试通过，新增`test_instruction_consistency.py`覆盖全部水果情境的槽位、8类组合的阶段顺序、15种B1负载的准备顺序/初态/送达检查及统一提示词。

仿真级（research初态，高速直采，6进程，每实例1条，独立重放误差0）：

| 批次 | 结果 |
| --- | --- |
| 受影响子集 seed 0（L1/L2/D01/D02/B1全部＋C05/D09香蕉） | 35/35直采合格 |
| 全目录 seed 0 | 114/114直采合格 |
| 全目录 seed 1 | 114/114合格（113直采、1退回原流程）；19个香蕉实例在seed 1失败、换seed 2合格 |

物理核对（seed 0）：

- 所有水果最终位于餐盘局部x −0.104～−0.119m，主食+0.108～+0.112m；带负载B1送达前后负载相对餐盘位置不变。
- L1/L2/D01/D02香蕉最终长轴与餐盘Y轴夹角余弦1.0（前一天数据为0.002，即未转向）。
- C05/D09香蕉组合的动作与状态和前一天同seed数据逐元素一致；只有第二语言阶段起点前移到水果技能结束时刻（C05 banana/burger：16500→15880 tick）。
- 前一天100实例中85条仿真时长完全相同，变化的正是15条改了落点的L1/L2/D01/D02：香蕉转向使L1 +0.6s、D01 +1.6s、L2 +10.8s、D02 +10.0s（清洗后香蕉转向本来较慢，组合中的L2香蕉阶段一直如此），其余水果±2s。带负载B1录制段22.7–22.8s，空盘20.9s；录制前准备平均8.1s墙钟。

seed 1的19个失败全部是香蕉：15个组合与前一天相同（洗后香蕉转向后放盘IK无解、主食接近路线不可用或主食放置停滞，原流程同样失败）；新增L2/D02香蕉——现在也先转向，于是继承了组合里同一个“洗后转向放盘IK无解”（前一天不转向时seed 1可过）；新增B1香蕉＋汉堡/热狗——录制前准备复用C05/D06的放置，继承同样的主食放置失败。C05香蕉/汉堡退回原流程与前一天相同。换seed不影响数据量，但这些香蕉初态在相应任务中会缺数据。

全目录墙钟462秒（seed 1为588秒）（前一天100实例288秒）不可比：采集时本机另有Isaac Sim（约3.2核）和网球视觉节点运行，负载平均14–15/12逻辑核；同100实例单样本墙钟总和1635→2412秒，但仿真时长6610→6624秒，未改动任务也同样变慢。

## 边界

- 旧L1/L2/D01/D02数据（水果在中心、香蕉不转）和旧组合阶段边界与新约定不同，训练不要混用。
- 洗后香蕉转向放盘在部分初态（如seed 1）规划失败，原子L2/D02和带香蕉＋主食的B1现在也受影响；属既有规划局限，未在本次处理。
- 微波炉加热/清洗计时、已洗/已加热等不可见状态造成的歧义不在本次范围（见此前MEM分析）。
- 只验证了seed 0/1的research初态；真实设备未涉及。
