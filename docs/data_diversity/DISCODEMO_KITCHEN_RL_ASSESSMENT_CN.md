# Kitchen 数据多样性与特权状态 RL 适配评估

日期：2026-11-08。评估基线：`feature/data-collection-improve`，HEAD `395d8295e4669127f82722ae329e58ea261ae543`，开始检查时工作区干净，未配置 upstream。

本文是文献调研、源码审计和接口微基准，**不是已经实施的 RL 方案或 VLA 效果实验**。本轮只增加评估文档与微基准结果，未修改仿真、控制器、任务目录、采集逻辑或环境依赖。

## 1. 评估结论

**值得建设一层可供 RL、规划和策略评估共同使用的状态与任务环境接口；值得做小规模特权状态 RL 数据生成实验；当前不宜直接把所有长任务迁移成端到端 DiscoDemo。**

这三个判断需要区分：

| 决策 | 建议 | 理由 |
| --- | --- | --- |
| 统一真实状态、动作步进、任务证据、状态重置接口 | 优先做 | 大部分底层能力已存在，即使最后不用 RL，也能用于多解规划、恢复数据、VLA 闭环评估和采集筛选 |
| 用特权状态 RL 生成示范，再交给视觉策略模仿 | 做原子任务试点 | 和现有 MuJoCo、无图像 H5、后续离线 Unity 渲染的分层吻合，有机会增加闭环恢复与同初态多解 |
| 直接复制论文训练配置与 Isaac Sim 工程 | 暂不做 | 物理引擎、夹爪、动作、步频、并行规模、任务长度均不同，移植不等于加一个 Gym 包装 |
| 所有 100 个具体任务分别从头训练 RL | 暂不做 | 长链探索与重复训练成本高；应先复用按物体/目标条件化的原子技能，再验证组合的衔接分布 |
| 仅多换 seed、提速或加逐帧动作噪声 | 不足以解决问题 | 初态覆盖、时间变化、成功解法覆盖和纠错覆盖是不同维度 |

目前缺乏当前数据集的正式覆盖指标和 VLA 闭环结果，因此能确认的是**生成机制容易收敛到少数解法**，不能给出“现有多样性不足导致成功率下降了多少”的数字。

## 2. 论文到底做了什么

主文和附录依据用户提供的 [DiscoDemo 本地 PDF](<DISCODEMO: DISCOVERING EFFICIENT AND DIVERSE demenstrations for IL.pdf>)；本地文件 SHA256 为 `891fc5b4a6d2a1538ecf2e43b87686dad0b06265fd9125a0dc6d89fd3f0d1c0e`。另核对了作者的[项目页](https://davian-robotics.github.io/DiscoDemo/)、[公开代码](https://github.com/DAVIAN-Robotics/DiscoDemo)、训练配置、训练入口、多样性奖励实现和导出脚本。

论文研究的是：**训练一个知道仿真真实状态的 RL 示范生成器，让它针对同一任务找到多种成功解法；最终部署的 VLA 并不获得这些真实状态。**

核心流程如下，定位见主文 §3、附录 A/B/D：

1. 每个任务从 20 条成功的人类示范起步；示范状态作为课程重置候选，示范转移也进入训练 minibatch，并非只看示范终点。
2. 采用逆向课程：先从接近成功的状态训练，再逐渐向示范开头移动；每条示范有独立前沿。前沿最近 10 次有效边界起始实验成功率达到 0.9 就后退 16 帧，半数示范从头可完成后切到正常初态分布。
3. 每个 episode 抽取固定的 3 维潜变量 z，策略根据真实状态和 z 选择动作。不同 z 引导不同解法。
4. 奖励结合任务成功、METRA 状态位移多样性和不良接触惩罚；**只有整条 episode 成功，其转移才获得多样性奖励**。实现用 episode ID 在结束后回填成功门控，尚未结束的 episode 和原始示范没有多样性奖励。
5. 冻结生成器，从正常初态采样轨迹；失败和违反物理筛选的成功轨迹被剔除。保留数据再渲染图像、转换为训练数据，微调 π0.5。

任务成功门控非常关键：没有它，多样性可能只是“把东西甩到不同地方”。单纯加普通 SAC/PPO、探索噪声或熵奖励，也不能等同于实现了 DiscoDemo。

### 2.1 效果证据与适用边界

论文四个任务是香蕉入碗、方块堆叠、两种插接。主文报告 π0.5 平均成功率：仿真约 62%，最强基线约 40%；实机约 78%，最强基线约 39%。这是作者在其任务、模型和数据上的结果，不是我们厨房项目的预期收益。[作者项目页](https://davian-robotics.github.io/DiscoDemo/)

本地 PDF 的重要细节：

- 每个生成方法最终使用 3,000 条成功示范；H20 只有原始 20 条。评估多样性贡献时，更重要的对照是数据量一致的 P-RFCL（α=0）和 DiscoDemo，而非只与 H20 比。
- 全数据集 coverage 与下游成功率的相关性，比单一初态下“轨迹看起来不同”的 diversity 更稳定；但每任务仅比较七种生成方法，这种相关性不能当作普遍因果定律（§4.3、E.1）。
- α 越大不保证越好；过强的多样性会损害任务能力。主实验 α=0.3，不能直接复制成我们场景的最优值。
- 安全惩罚不能替代导出过滤。附录 E.3 的香蕉与插接例子中，即使加了 shaping，**成功轨迹**的过滤通过率也只有约 50% 和 46%；生成成功率不等于最终可用数据产率。
- 其 MP 基线是一个不进行碰撞推理的脚本规划器（附录 C），与我们现有局部几何检查并不相同。不能由其 MP 表现弱，直接推断本项目规划数据一定不能训练 VLA。
- PLD、ExpertGen、PGDG 使用了作者的适配或重实现，结果不是所有原论文最佳配置的统一排名。
- 仅覆盖四类较短的单臂桌面任务，不能直接外推到双臂带载送盘、清洗/加热状态机和数分钟长链。
- 多种成功解法与纠错数据互补。论文的 DAgger/DART 对照说明，做了多解发现也仍需考虑偏离示范后的恢复（§4.5）。

### 2.2 论文的效率依赖什么

附录 A/B/F.4：120Hz 物理、20Hz 策略、单臂 8 维动作、45 维特权观察；任务 horizon 为 20/30s。生成器使用 FlashSAC，在单张 B200 上以 2,048 个并行环境训练 50M environment transitions；一半 minibatch 来自示范。50M 是所有环境合计的转移数。

作者项目页的约 15 GPU 小时/任务涵盖生成器训练、生成和渲染，不包括示范采集、建场景或下游 VLA 微调。论文 F.4 还说明，部分训练时间由短段吞吐测量外推。这些数字**不能当成本机厨房训练耗时**。[项目页的成本口径](https://davian-robotics.github.io/DiscoDemo/)

公开依赖固定到 Python 3.11、Isaac Sim 5.0、Isaac Lab 2.2 和 Torch 2.9.1；当前项目是另一套 MuJoCo/Python 环境。[作者依赖文件](https://github.com/DAVIAN-Robotics/DiscoDemo/blob/main/pyproject.toml)

## 3. 我们当前具体缺哪种多样性

| 维度 | 当前机制与局限 | 建议 |
| --- | --- | --- |
| 任务/目标种类 | 100 个具体 case：20 原子、80 组合；这是语义覆盖，不等于每个 case 有很多行为模式 | 保留去重任务表，按技能族和目标统计样本，不把组合数量当成运动覆盖 |
| 初始物体位置 | research 初态局部 XY ±8cm、yaw ±5°，保持左右分区、组内主食/小盘关系及不重叠检查 | 在既定范围内分层抽样、记录接受/拒绝分布；不为追求多样性扩大到不可达或交换左右 |
| 初始设备/上下文 | 门只允许关闭或 100°；原子准备和状态驱动加热已经存在 | 分层覆盖合法门状态、目标物在炉内/外、盘上已有内容；保持任务前提，不机械地产生所有状态笛卡尔积 |
| 同一初态的成功解法 | 规划大多按固定候选顺序选可行抓点/路径；部分 IK fallback 有固定种子搜索 | 同一完整初态试多个通过几何和物理检查的抓姿、路线、落点；学习生成器进一步发现闭环解法 |
| 时间/平滑 | 离线连续平滑与 retiming 已明显改善速度，但大多沿原路线；每个样本只选最快合格候选 | 保留合理的速度范围，但不要把单一路线不同倍率计为独立解法；增加几何多解生成 |
| 偏差与恢复 | 主要保存成功专家执行，重试通常换新初态；没有系统的扰动后恢复库 | 从可达偏移状态重新规划并物理执行成功，后续再做真正的 learner-state DAgger |
| 组合衔接 | 原子独立采集初态和组合中真实衔接姿态不同；负载和盘上占位也不同 | 使用上游实际执行得到的状态训练/验证下游，不能只拼接原子动作数组 |
| 视觉 | 当前原始数据没有训练图像 | 后续独立渲染相机、光照、材质；视觉随机化不能补足运动/恢复覆盖 |

源码依据：[任务矩阵](../../integration/kitchen/tasks/catalog.py)、[随机初态](../../robot_arm/kitchen/research_initialization.py)、[专家](../../integration/kitchen/planning/expert.py)、[当前优化选择](../../integration/kitchen/data/optimized_collection.py)。现有任务语义和约束继续以 [V3 任务文档](../kitchen_platform_v3_20261020/TASK_CATALOG_V3_CN.md) 为准。

**当前“优先取最快合格轨迹”的选择规则，与“保留多个有效行为模式”有不同目标。** 未来多解生成后，建议先按成功、接触质量和时长上限筛选，再在可用池中按初态桶、路线/抓姿模式、恢复类型分配配额或选覆盖子集。仍然保留每条原始专家备份，但不自动把所有倍率版本都加入训练集。

### 4.1 必须注意的现有边界

检查代码时，`ENFORCE_CONTACT_GUARD=False`、`ENFORCE_CONTACT_POLICY=False`、`ENFORCE_COLLISION_CERTIFICATE=False`。关节和命令 TCP 限速仍在，但不能因此声称实测 TCP 速度与不良接触力在所有运动步骤都被在线拦截；manifest 中部分历史描述也不能代替实际开关。

这些开关来自前期用户允许的 task-only 采集策略，本轮不改变。对随机探索策略，**最终目标成功不足以约束过程**：它可能推小盘、撞门、挤压桌沿，最后仍把物体留在目标区域。未来 RL 设施应有明确、独立版本的探索/导出接触标准，先以现有成功示范校准合法接触，再决定哪些异常终止、哪些作为软惩罚、哪些在导出时剔除。不能直接照搬论文的 50N/20N 或把旧开关全开而不回归。

当前 `get_task_feedback` 有意返回 `task_success=NOT_VERIFIED`。真实成功由 integration 层校验。这个职责边界应保留：底层给事实，上层 evaluator 判定所选任务是否完成。

## 5. 建议的最小环境契约

以下均为**拟议接口**，尚未实现；不需要重写模型、IK 或低层控制器。

```text
reset(seed, task_spec) -> privileged_obs, info
step(action) -> privileged_obs, reward, terminated, truncated, info
query_state(ids, detail) -> 现有语义状态接口
task_evidence() -> predicates, hold_seconds, subgoals, success, failure_reason
capture_reset_state() -> 完整环境快照
restore_reset_state(snapshot) -> privileged_obs, info  # 仅 episode 开始前
```

Gymnasium 的 `terminated` 和 `truncated` 必须区分：任务成功/定义内失败与外部时间上限有不同 bootstrap 语义；向量环境还需保留 reset 前的 final observation。[官方环境契约](https://gymnasium.farama.org/api/env/)

### 5.1 分清三种“状态”

**A. 用来完整恢复环境的内部快照。** 保存 MuJoCo integration state/warmstart、所需前向动力学缓存、控制器 previous/accepted/reference/frame_step/tick/stop 状态、设备计时器与按钮 latch、任务稳定窗口/进度、环境 RNG、必要的接触策略状态、模型/控制/语义版本。环境队列可约束为控制边界且无未消费批次，避免不必要的恢复范围。

MuJoCo 官方也明确，完全复现需要保存所需 integration state，warmstart 的微小差异可能随接触放大。[确定性与重现边界](https://mujoco.readthedocs.io/en/stable/computation/index.html#reproducibility)

**B. 生成器的特权观察。** 先采用任务相关的固定数值结构：活动臂关节/速度、实测夹爪宽度与执行状态、TCP、目标/载体/餐盘位姿与速度、TCP 相对位置、设备关节/计时/标记、上一接受动作和任务目标编码；必要的其他障碍/另一臂状态按固定字段或带 mask 的对象表补充。不能只给 qpos 而省略影响下一步行为的计时与控制历史。归一化边界来自关节限制和有效工作区，并监测越界，不用狭窄示范统计把恢复状态全裁掉。

**C. VLA 的可部署观察。** 继续是图像、语言和机器人本体状态；不把物体真值、heated/cleaned 标记、成功标签或 z 塞进 VLA 输入。生成器的 state 和训练 latent 可以作为旁侧 provenance 保存。设备计时等隐藏信息还要检查是否能由可见状态/历史推断，避免生成需要学生“读仿真内部变量”才能模仿的分支。

B 可以比 A 精简，未必观测完整求解器变量；但应足够支撑闭环。A 的严格恢复和 B 的近似 Markov 特权观察不能混称。

### 5.2 动作与执行

先做单臂 8 维试点：7 个受限关节增量 + 1 个夹爪开度目标，另一臂保持已验证姿态；以后扩展双臂 16 维。关节增量以**前一有效目标**和明确的步长尺度还原，经过现有 `prepare_joint_targets` 等限幅与控制执行，不绕开原控制器。

RL 内部动作形式可以与训练 H5 不同，但最终保存的是 25Hz **实际接受的关节位置目标与夹爪开度**，不是未限幅请求、关节速度、实测下一帧关节位置或补偿后的 actuator ctrl。两侧顺序、开度 ratio 与米的区别沿用 [现有 LeRobot 契约](../kitchen_platform_v3_20261020/LEROBOT_PI05_CN.md)。

现有公开 API 在夹爪变化时要求 guarded stationary phase 或显式 contact contract，不能把任意 16 维网络输出直接丢进去。建议在环境适配层依据真实接触和任务目标管理有界接触权限，保持一次动作一步物理的连续交互；不能每步执行完整规划器，也不能靠指定预录 skill 时间表强制策略重复脚本。第一试点可以保守地限制开合时机，须明确这会限制解法范围。

### 5.3 任务 evaluator 与奖励

把可复用的物理谓词与“持续多久”记忆分开，返回结构化证据，供在线 RL、最终数据过滤和独立重放调用同一语义版本。原有验证函数仍可作为采集验收入口；**不能只调用 `validate_final` 而忽略技能验证**，例如门与加热原子的条件目前部分位于 `validate_skill`。

- 保留实际稳定支撑、完整包络、手指分离、自己的主食盘承托、清洗/加热标记、送盘倾角与已放物品保留等要求，不为 RL 方便降低成功标准。
- 长任务用由物理事件驱动的任务进度记忆，遵守英文指令顺序；不能只看最后“都在盘上”，也不能相信策略自报已洗/已热。
- 清洗 2s、加热 5s 是当前仿真设备语义，不是物理清洁度或温度测量；在特权状态训练中也必须如实标注。
- 初版先做稀疏成功奖励 + 经校准的不良接触惩罚，配示范逆向课程；若确实需要距离/姿态 shaping，明确增加一个对照条件，避免奖励近似变成固定路线追踪。
- 不直接复制 `.99` 折扣到长链：25Hz 下 150s 是 3,750 步，`.99^3750` 约 `4.3e-17`，说明远端稀疏奖励的折扣影响很大。先缩短到技能任务，并按物理时间尺度评估折扣、n-step 和课程。
- 多样性表征优先看目标物、载体与活动 TCP，排除时钟、episode ID、RNG、无关物体和纯动作噪声，防止靠空动另一臂或抖动“刷多样性”。成功门控仍不足以阻止无意义绕路，需同时评估时长、路径效率和接触质量。

### 5.4 逆向课程不需要让原始 H5 膨胀

H5 已足够从头重放，但中段 qpos/qvel 不包含当时的全部设备计时、控制插值与任务稳定窗口。建议：

1. 保留原始 H5 不变；在匹配模型/控制版本中从头重放一次。
2. 在技能边界和少量阶段锚点捕获完整环境 snapshot，单独缓存并绑定源 H5 SHA256、tick 和语义版本。
3. 需要更细课程时在锚点间重放动作前缀，按实测成本决定缓存间隔；不预先加密集接触日志。
4. 对锚点做恢复后同动作的一步/多步等价检查，覆盖持物、按钮 latch、清洗中和加热中等状态。
5. 训练时可以从中段开始；**最终用于完整任务示范的数据应由正常初态闭环执行得到**，不能把终点附近课程片段冒充完整任务。

模拟器训练 reset 时恢复合法历史状态，与一条已开始的示范中途修改物体状态是不同操作。最终录制仍须从一次初态开始，仅执行动作并独立重放。

## 6. 吞吐微基准与后端选择

本次环境未安装 Torch/JAX/Gymnasium/SB3/MJX/Warp，`nvidia-smi` 无法与驱动通信。这里只说明本次进程不能验证 GPU 训练，不判断其他训练机的配置，也未安装或更改依赖。

## 7. 先做什么实验，才能决定 RL 值不值得继续

### 7.1 第一阶段：接口和覆盖基线

先建立统一数值状态、结构化任务 evidence、原子化 step 和完整 snapshot reset。最小验证包括：查询不推进/不改变物理；步进恰好推进 20 tick；控制限幅语义不变；从合法持物/设备工作锚点恢复后，同动作恢复相同后续物理与设备/任务记忆；超时 final observation 不被 reset 覆盖。

先选 **L1 apple 和 R5 hotdog**：一侧普通抓放、一侧抓主食载体且食物保持承托，可覆盖两类常见接触。随后测试 L1 banana 的异形抓持和 R3 的关节设备操作；L2/R1/R2/R4、带载 B1 与完整 D09 后移。此顺序是建议，不是已经启动的实验。

现有一条成功备份可验证软件管线，但不足以证明课程有足够的接触与初态覆盖。先按位置桶收集少量成功种子示范，逐步增加，别直接承诺每任务 20 条或 3,000 条是最佳规模。

### 7.2 第二阶段：必须包含的对照

| 条件 | 目的 |
| --- | --- |
| A：现有脚本 + 相同初态分布 + 当前平滑/提速 | 现有质量/效率基线 |
| B：有限几何多解 + 同初态试跑/成功过滤 | 检查是否只需改变抓姿、曲线/落点候选的选择，而不用付出训练成本 |
| C：特权状态 RL + 示范逆向课程，α=0 | 测量闭环学习/课程本身收益，防止把全部收益误归于多样性奖励 |
| D：在 C 上增加 z 与成功门控多样性 | 测量多解发现的额外收益；先少量权重和固定调参预算，避免照搬 α=0.3 |

B 可以用低维平滑样条/路线参数扰动与覆盖选择，保持水池、炉口的受限走廊；如果用 CEM 等搜索，也只优化少数几何参数，不对几千帧关节目标加独立白噪声。它比完整 RL 更容易利用现有成功筛选，但覆盖通常仍围绕已有技能结构。

恢复实验可另加“有界扰动→基于当前真实状态重新规划→成功保留”。当前专家不是已验证的任意状态动作 oracle，不能把它自动称为 DAgger。真正 DAgger 要等学生闭环后，在学生访问的状态获得可信教师标签；若仅复制原脚本时间索引动作，会产生错误监督。

### 7.3 衡量有效多样性

建议首先对每个试点固定若干完整初态，分别生成多条解法；另外使用独立随机初态评价总体覆盖。以下指标一起记录：

- 成功率、接触过滤通过率、最终合格条数/总尝试和每墙钟小时可用条数；明确是否含训练、备份、候选、重放、渲染。
- 模拟时长、有效运动时长、路径长度与抖动/不良接触；不要靠绕远、重复停顿或空动无关手臂扩大指标。
- 固定初态 diversity 与全分布 coverage 分开；匹配相同样本数、初态桶和成功定义。
- 可参考论文 E.1 的目标物/TCP 轨迹→统一长度→DCT→RBF→Vendi score。其方法重采样 64 帧、去 DC 后保留 8 个系数；Vendi 随集合大小变化，需要固定子集大小，不能直接比较 10 条与 1,000 条的数值。
- 厨房按活动臂、目标物/载体、餐盘及语义阶段扩展特征；位姿距离/旋转连续性要处理，尽量使用对象相对坐标，避免纯初态平移主导“解法不同”。
- 论文去掉 DC 会弱化绝对落点差异，因此另外记录初态分箱覆盖、合法目标区域、落点/抓姿模式和恢复状态覆盖；度量统计与 kernel 尺度在训练/开发数据冻结，不能看测试集调参数。
- 双臂指标包含真实活动/载物关系，防止仅无关臂运动就被认为高覆盖。

**最终判据仍是下游策略闭环成功率。** 图像还未接入时，可以先用同一低维模仿学习基线验证分布覆盖、恢复与接口，再通过小样视频审查；这只是代理证据，不能据此宣称 π0.5 获益。Unity 图像准备好后，再在相同视觉配置、训练 recipe、数据量/帧数和评估初态下比较 VLA。

数据条数相同时，长轨迹含有更多训练帧；建议同时报告等 episode 与等有效帧预算的结果。评价集分开看正常随机初态、预先固定的边缘初态、可达偏移/恢复状态和未训练组合；每种方法使用同一测试实例，并报告置信区间和多个训练种子。

### 7.4 扩展/停止条件

只有当 C 能在正常初态稳定解决原子任务且物理过滤后产率可接受，才加 D 的多样性。D 如果只提高 Vendi、同时增加时长/接触失败或没有模仿策略收益，不作为扩展依据。

如果 B 已在同等采集预算下达到与 D 接近的有效覆盖及下游表现，优先选择维护成本低的 B；如果 RL 在未见偏移和组合交接状态上明显更好，再扩展到设备操作与带载双臂。训练步数和调参预算需在正式实验前依据吞吐测量固定，本报告不预先承诺训练小时数或成功率。

## 8. 组合任务与数据格式如何接回现有流程

原子技能学会后仍需从**真实上游执行状态**启动下游。盘上水果可能阻挡主食，香蕉朝向影响剩余空间；B1 需要保持所有食物的支撑链。单独原子成功率高，不保证组合连续执行成功。

组合阶段由任务/英文指令选择，原子策略按当前真实状态闭环执行；前置条件、完成条件和已完成目标保持由同一 evaluator 监控。不能重新回到 home、重置物体或拼接独立示范的 qpos 来修补衔接。主食加热 H 仍按真实门/炉内/加热状态选择步骤，已有顺序明确的粗指令不能为增加多样性任意打乱。

建议保留现有流程，并在动作候选之前增加“生成器”入口：

```text
任务和合法初态
  → 脚本多解 / 特权状态 RL 生成器
  → 成功 + 过程接触质量 + 效率约束
  → 按初态和行为覆盖选样
  → 现有可选平滑提速、同初态物理检验
  → 最终 H5 录制与独立动作重放
  → 可选重新检查覆盖，防止后处理抹平差异
  → 英文粗/细标注 + manifest
  → 离线 Unity 图像 → LeRobot → VLA
```

原始 H5 继续记录一次精确初态、关节位置/夹爪动作和关键状态，不加所有训练 replay buffer、不加密集中途检查日志。接触安全统计可在线累计峰值、持续时间、冲量和少量超限事件，写小型旁侧验收报告；若要保证不漏 2ms 短时峰值，需要在物理子步累计，不能只采样 25Hz 后声称捕获全部峰值。

保留首条成功专家备份作为种子/基线，不覆盖历史数据；RL 权重、训练转移 buffer、课程锚点缓存与最终数据集分目录管理。建议新增的旁侧 provenance：generator 类型/版本/checkpoint、seed、完整初态哈希、行为 latent/模式、源示范 SHA/tick、奖励/成功/接触语义版本、后处理父轨迹组。

现有 `postprocessing.source_group` 只解决同一原始轨迹的备份/优化/语言视图分组。未来还应把同初态的不同 latent、路线变体、同源恢复轨迹纳入同一 split group；相同初态跨不同方法用于配对比较可以，但同一方法训练/验证之间不能泄漏。同一语义阶段的训练 action chunk 不跨语言边界，继续沿用 [已有粗/细导出规则](../kitchen_platform_v3_20261020/LEROBOT_PI05_CN.md)。

多解本身会带来同一观察下多个合法动作，这是生成式 VLA 可以建模的目标分布，但仍要防止行为切换造成不连续。不要把 z 改写成不存在的用户指令；检查当前视觉/机器人历史是否足以区分进行中的模式，并实际验证 chunk 执行后的闭环一致性。
